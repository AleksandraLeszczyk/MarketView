# reports itself unavailable and the classifier is unaffected.

# The same two also cover the TimeToChange3 day-range model
# (agent_stonks/dayrange_model.py), which is the only thing here that needs
# both at once: its blend is one LightGBM pair and two torch networks.
#
# NOTE: torch and lightgbm each bundle their own OpenMP runtime and this
# environment has no system libomp for them to share, and the conflict cuts
# both ways. A process that imports torch first segfaults when it later loads

# ahead of torch. That ordering then arms the opposite trap -- with LightGBM's
# runtime loaded first, the next torch op that goes parallel takes the process
# down (a MaxPool1d on a tiny tensor is enough) -- so dayrange_model.py also
# calls torch.set_num_threads(1) at import, which works whatever the order was.
